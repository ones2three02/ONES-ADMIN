# ONES-ADMIN 前端引导式交互治理规范

版本：v0.0.144
日期：2026-07-07
定位：企业级后台前端交互治理基线，约束后续登录页、HRMS 页面、系统管理页面和新增业务模块的交互方式。

## 1. 背景

ONES-ADMIN 已完成 Vben Admin / Ant Design Vue 选型，并在 v0.0.138 至 v0.0.142 先后治理登录页图标加载、后台列表稳定高度、共享分栏布局、前端布局治理报告和工作区状态条。当前问题不再是单个按钮或单个页面样式，而是整体交互语言还需要更符合主流企业级后台用户习惯。

本规范用于解决以下问题：

- 用户进入页面后，应能立即判断当前页面能做什么。
- 用户筛选、选择范围、上传、导出、提交、删除时，应能知道当前操作对象和影响范围。
- 页面不应依赖大量说明文字教学，而应通过默认状态、主动作、空态、反馈和渐进式入口自然引导。
- 所有新增页面必须保持 Vben / Ant Design Vue 风格，不另起一套视觉体系。

## 2. 设计原则

### 2.1 先给路径，再给能力

页面首屏必须让用户看懂三件事：

1. 当前对象：例如员工、合同、字典项、文件资产。
2. 当前范围：例如全部部门、当前部门、当前员工、当前预警窗口。
3. 下一步主动作：例如新增员工、签署合同、上传花名册、选择字典类型。

避免把所有能力平铺在首屏。高级能力进入 toolbar、dropdown、抽屉、更多操作或详情页。

### 2.2 一个工作区只保留一个主动作

每个工作区只允许一个视觉上最强的主动作。其他动作按重要性降级：

- 主动作：`Button type="primary"`，只放当前阶段最自然的一步。
- 次动作：普通按钮或 link button，例如刷新、清空范围、导出。
- 风险动作：进入 `VbenTableAction` 的 dropdown，并保留 danger 状态和确认弹窗。

### 2.3 状态替代说明

企业后台不应堆大段介绍文案。页面引导优先通过状态表达：

- 当前范围使用 `GuidedWorkbenchBar` 或同类轻量状态条。
- 当前筛选使用可见的条件摘要、标签或表单值。
- 当前不可操作原因使用 disabled 状态加 tooltip 或短提示。
- 空数据使用 Ant Design Vue `Empty` 加一个可执行主动作。

### 2.4 渐进式披露

用户第一次进入页面时只看到高频路径；需要时再展开复杂能力：

- 登录页默认展示账号密码登录，二维码作为右上角角标，飞书、SSO、手机入口使用 icon 化按钮。
- 列表页默认展示常用筛选；更多筛选放到可折叠查询区或表格 toolbar。
- 员工档案、合同附件、资料附件等信息放入抽屉或分栏详情，不挤压列表主工作区。
- 花名册导入、未来请假审批等流程型页面使用步骤状态和上传结果反馈，不把规则说明铺满页面。

### 2.5 操作闭环

所有交互都必须形成闭环：

- 操作前：可判断当前对象、权限、风险和必填条件。
- 操作中：有 loading 或禁用状态，避免重复提交。
- 操作后：成功、失败、取消各有明确处理。
- 失败时：错误信息可见，保留 TraceId 或业务化定位信息。

### 2.6 稳定布局优先

页面引导不能破坏企业后台高密度使用体验：

- 列表页表格必须保持稳定高度，优先 `height: '100%'` 和 `autoResize: true`。
- 左右分栏页面优先复用 `SplitListLayout`。
- 页面说明、空态和提示条不能导致表格区域持续变小。
- 移动端允许纵向堆叠，但不能出现横向页面级滚动。

## 3. 页面类型规范

### 3.1 登录与认证页

登录页是企业系统第一印象，但不能做成营销页。

推荐结构：

- 左侧视觉区保留 ONES / 1S 企业视觉、白天/夜间资源切换和少量能力节点。
- 右侧认证区保持紧凑，默认账号密码登录。
- 二维码登录放右上角折角入口，点击进入二维码页面。
- 第三方登录只使用 icon 按钮，飞书优先，SSO 次之，手机登录作为补充。
- 第三方入口必须有 tooltip / aria-label；配置缺失时提示“管理员尚未配置”，不显示长说明。
- 登录失败后重置验证码，保留错误原因和追踪 ID。

验收标准：

- 右侧认证区不出现大段能力介绍。
- 登录按钮是唯一主动作。
- icon 在白天和夜间模式下清晰可见，切换主题不闪烁、不重排。
- 飞书和 SSO 只做授权跳转，App Secret、回调换 token 和账号绑定必须由后端完成。

### 3.2 列表与检索页

适用于员工、合同、用户、角色、接口资源、文件资产、审计日志等页面。

推荐结构：

- 页面标题只描述业务对象，不写营销式副标题。
- 查询表单使用 Vben 表单能力，默认展开高频条件。
- 表格 toolbar 保留刷新、列设置、搜索折叠、密度等 Vben 原生能力。
- 当前范围通过状态条或表格标题表达。
- 空态必须说明当前范围下没有数据，并提供主动作或调整筛选入口。

验收标准：

- 用户能一眼判断当前列表受哪些条件影响。
- 筛选值变化后数据刷新有明确 loading 状态。
- 无数据时不是空白页面，至少有“新增”或“清空筛选”路径。
- 表格高度稳定，固定列、横向滚动和分页不挤压页面。

### 3.3 左右分栏工作台

适用于部门范围 + 用户/员工列表、员工范围 + 合同列表、字典类型 + 字典项等页面。

推荐结构：

- 左侧只放范围选择、搜索、清空范围和空态。
- 右侧顶部放 `GuidedWorkbenchBar`，说明当前范围和下一步动作。
- 左侧选择发生变化时，右侧标题、状态条和表格数据同步变化。
- 左侧搜索无匹配时提供“清空搜索”入口。

验收标准：

- 未选择范围时，右侧能明确提示“请选择左侧对象”或“当前查看全部范围”。
- 已选择范围时，右侧能明确展示选中对象名称。
- 清空范围是可见动作，但不抢主动作层级。
- 分栏宽度稳定，不使用页面级临时 margin 拼接布局。

### 3.4 抽屉表单

适用于新增、编辑、调岗、转正、离职、签署合同、终止合同等操作。

推荐结构：

- 抽屉标题包含动作和业务对象，例如“调岗 - 张三”。
- 表单字段按业务语义分组，不把无关字段平铺。
- 默认值必须明确，编辑场景不能覆盖原值。
- 提交按钮固定在底部操作区，取消和提交层级清晰。
- 复杂流程动作应展示影响说明，例如离职会影响在职状态和生命周期记录。

验收标准：

- 必填字段有明确校验。
- 提交中禁用按钮并显示 loading。
- 成功后关闭抽屉并刷新来源列表。
- 失败时保留表单输入并展示业务化错误。

### 3.5 批量导入与流程页

适用于花名册导入、未来考勤导入、请假审批、薪资核算等流程型页面。

推荐结构：

- 先显示当前步骤：下载模板、上传文件、解析结果、处理错误。
- 上传区只承载上传动作和格式约束，详细规则放折叠说明或文档链接。
- 导入结果必须有成功数量、失败数量、错误明细入口和重试路径。
- 错误行默认脱敏展示，敏感字段查看必须走权限。

验收标准：

- 用户能知道当前停在哪一步。
- 失败结果可追踪到批次和错误行。
- 允许用户下载模板、重新上传、查看错误明细。
- 导入过程有 loading 和重复提交保护。

### 3.6 高风险操作

适用于删除、禁用、离职、终止合同、移除附件、发布 Manifest 等操作。

推荐结构：

- 风险动作不放主按钮位置，优先进入行操作 dropdown。
- 必须使用确认弹窗。
- 确认文案说明对象名称和影响范围。
- 后端失败必须展示业务化错误，不吞掉异常。

验收标准：

- 用户取消时不提示错误。
- 接口失败时恢复原 UI 状态。
- 操作成功后刷新相关数据。
- 高风险写接口仍需后端权限、审计和 TraceId。

## 4. 共享组件治理方向

当前已存在：

- `SplitListLayout`：统一左右分栏列表布局。
- `GuidedWorkbenchBar`：统一工作区范围和下一步动作提示。
- HRMS 共享错误、文件、上传、下载、状态切换反馈工具。

后续建议新增或扩展：

| 组件或工具 | 目标 | 适用场景 |
| --- | --- | --- |
| `GuidedEmptyState` | 统一空态文案、主动作和清空筛选入口 | 员工、合同、用户、文件、接口资源 |
| `ActiveFilterSummary` | 可见化当前筛选条件和一键清空 | 高筛选密度列表 |
| `RiskActionConfirm` | 统一危险操作确认、取消静默和失败反馈 | 删除、离职、终止、停用 |
| `ProcessResultPanel` | 统一导入、发布、批处理结果展示 | 花名册导入、Manifest 发布、未来薪资核算 |
| `ScopedWorkbenchHeader` | 将工作区状态条、范围标签、主动作组合成更稳定模板 | HRMS 新增假勤、审批、薪资模块 |

这些组件必须基于 Vben / Ant Design Vue，不引入新的视觉体系。

## 5. HRMS 页面验收矩阵

| 页面 | 当前要求 | 后续治理重点 |
| --- | --- | --- |
| 登录页 | 账号密码为主，二维码角标，飞书优先 icon，白天/夜间资源稳定 | 后端飞书 OAuth / SSO 回调完成后补真实状态和绑定提示 |
| 员工管理 | 部门范围、当前范围、员工空态主动作、稳定表格高度 | 抽取更通用的范围筛选和空态组件 |
| 合同管理 | 员工范围、合同历史、到期预警、导出反馈 | 合同签署/终止流程强化影响说明 |
| 花名册导入 | 模板下载、上传反馈、批次和错误明细 | 增强步骤引导和导入结果面板 |
| 资料预警 | 预警窗口、风险状态、附件查看和导出 | 补充空态和风险处理路径 |
| 系统用户 | 部门范围、用户空态、稳定表格高度 | 与员工账号绑定场景联动 |

| 文件管理 | 文件资产、受控预览、业务归属 | 补充业务归属筛选和异常访问反馈 |

## 6. 工程化验收清单

后续涉及页面交互的版本，至少检查：

- 是否复用 Vben / Ant Design Vue 组件体系。
- 是否只保留一个主动作。
- 是否有当前范围或当前对象提示。
- 是否有加载态、空态、错误态和成功反馈。
- 是否对风险动作提供确认弹窗。
- 是否保持表格稳定高度和横向滚动边界。
- 是否有中英文文案资源，避免业务页面硬编码扩散。
- 是否通过 `frontend-layout-report`、类型检查、单测或 Playwright 截图验证。

## 7. 版本边界

v0.0.144 只沉淀规范和版本记录：

- 不修改运行时页面。
- 不新增后端接口。
- 不新增数据库迁移。
- 不连接真实 MySQL、Redis、RabbitMQ 或 MinIO。
- 不改变 Vben / Ant Design Vue 选型。

建议后续版本：

1. v0.0.145：已按本规范治理扫码和手机号认证入口，明确未配置能力边界，并补齐登录字段自动完成、辅助入口待配置状态和可理解的 icon 标签。
2. v0.0.146：已新增项目状态与问题闭环审计，明确前端登录页、表格稳定高度、飞书/SSO 和 README 口径的已闭环与未闭环边界。
3. v0.0.147：已治理剩余 `height: auto` 的业务表格页面，前端布局报告中的自动高度页面数量降为 0。
4. v0.0.148：已完成生产安全基线，关闭默认演示账号初始化，补齐后端登录限流和公开端点保护；前端视觉保持不变。
5. v0.0.149：完成飞书 OAuth 后端闭环，再将真实认证状态反馈接回登录页。
6. v0.0.153：将高频引导能力抽取为共享组件并纳入前端布局报告。
