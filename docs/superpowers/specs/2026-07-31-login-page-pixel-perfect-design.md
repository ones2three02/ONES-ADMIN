# ONES-ADMIN 登录页像素级复刻设计规格

## 1. 目标

以用户提供的参考图
`/var/folders/tm/gbhh0ggd3bjgbpylhsqfg2x00000gn/T/codex-clipboard-c9d03d6e-d123-47b9-91af-5f1408812461.png`
作为唯一视觉真值，完整重构 `/auth/login`。

验收主状态为：

- 视口：`1536 × 1024`
- 主题：浅色
- 语言：简体中文
- 表单状态：用户名和密码已由测试流程填入，记住账号已勾选
- 页面状态：未登录、无校验错误、无加载态

主状态必须达到像素级复刻，不允许保留现有暗色科技稿的视觉元素，也不允许进行未经用户确认的二次设计。

## 2. 视觉原则

### 2.1 参考图优先级

布局位置、尺寸、字号、字重、颜色、透明度、圆角、边框、阴影和图标形态均以参考图为准。现有主题变量和组件默认样式与参考图冲突时，以局部登录页样式覆盖，不修改全站设计系统。

### 2.2 4K 清晰度

- 页面文字、边框、图标和几何界面元素使用真实 DOM、CSS 与图标库渲染，保持分辨率无关的清晰度。
- 3D 生态插画使用独立高分辨率资产，不将整页截图作为页面背景。
- 新增位图资产的源尺寸至少为实际最大显示尺寸的 2 倍；核心 3D 主视觉优先达到 4 倍采样或可满足 4K 桌面显示的源尺寸。
- 位图禁止经过有损二次压缩；透明资产优先使用 PNG/WebP 无损格式。
- 不放大低分辨率截图来伪造 4K，不使用模糊滤镜掩盖素材不足。

## 3. 页面结构

### 3.1 外层画布

- 全屏浅灰蓝背景。
- 页面主体四周保留参考图中的窄间距和大圆角白色画布。
- 画布内部为左右双栏，桌面主视口分界约位于页面宽度的 58%。
- 左右区域使用非常轻的浅蓝层次区分，不能出现深色大面积背景。

### 3.2 顶部品牌与工具栏

- 左上显示参考图同款品牌 Logo 与 `ONES-ADMIN`。
- 右上显示语言切换和主题切换控件。
- 控件尺寸、间距、描边、背景和阴影按参考图对齐。
- 默认显示简体中文与月亮图标；现有切换行为继续可用。

### 3.3 左侧品牌内容

从上到下包含：

1. `ONES / 1S` 品牌短标。
2. 主标题“新一代企业协同管理平台”。
3. 副标题“连接人、流程与数据，助力企业高效运营与持续增长”。
4. 四项能力：高效协同、流程驱动、数据洞察、安全可靠。
5. 以 `1S` 立方体为中心、连接六个业务节点的 3D 生态插画。
6. 四项指标：`20+`、`100+`、`10W+`、`99.9%`。

左侧文字必须使用真实文本，四项能力图标使用匹配参考图的现有图标库图标。3D 生态插画作为独立资产展示，不能用 CSS 方块或手工 SVG 仿制。

### 3.4 右侧登录卡

卡片包含：

1. 品牌 Logo 与 `ONES-ADMIN`。
2. 标题“欢迎回来”。
3. 副标题“登录您的账号，继续高效工作”。
4. 用户名输入框。
5. 密码输入框和密码可见性按钮。
6. “记住账号”与“忘记密码？”链接。
7. 主按钮“登录进入工作台”。
8. “其他登录方式”分隔线。
9. 飞书、企业微信、Google 三个带文字的圆形入口。
10. “安全加密登录，保障数据安全”提示。

卡片采用白色半透明质感、柔和阴影和参考图同款圆角。输入框、按钮和第三方入口必须保留 hover、focus、disabled、loading 状态。

## 4. 交互与业务边界

### 4.1 保留

- `/auth/login` 路由和 `AuthPageLayout` 认证壳。
- `authStore.authLogin → loginApi → POST /api/auth/login → completeLogin` 主链路。
- Token 存储、用户信息与权限码加载、登录成功跳转和成功提示。
- 登录失败提示与后端 `traceId` 展示能力。
- 飞书与企业 SSO/OAuth 跳转逻辑及 state 防重放链路。
- 忘记密码路由、语言切换、主题切换和二维码登录路由本身。
- 用户名 `autocomplete="username"`、密码 `autocomplete="current-password"`。

### 4.2 调整

- 移除前端滑块验证码字段和失败后的滑块重置逻辑。
- 移除参考图中不存在的二维码折角入口；二维码路由仍保留，不删除功能文件。
- “记住账号”只持久化用户名，不保存密码。
- 飞书、企业微信按现有配置工作；Google 未配置时保留同款视觉入口并显示明确提示，不伪造可用登录。
- 不在源码、配置或测试夹具中新增生产可见的固定管理员密码。

## 5. 组件边界

### 5.1 认证布局

`web/playground/src/layouts/auth.vue` 负责全屏画布、双栏结构、顶部品牌工具栏、左侧品牌内容和底部版权。

### 5.2 3D 主视觉

`web/packages/effects/layouts/src/authentication/ones-visual-stage.vue` 只负责呈现与裁切 3D 生态资产，不承载表单或认证逻辑。

### 5.3 登录表单

`web/playground/src/views/_core/authentication/login.vue` 负责字段、校验、记住账号、第三方登录入口和调用现有认证 Store。允许为实现参考图结构而替换当前 `AuthenticationLogin` 外壳，但不得复制或绕过 Store/API 行为。

### 5.4 国际化

继续复用 `zh-CN` 与 `en-US` 认证文案资源。中文主状态像素级对齐；英文状态需要完整可读、不得截断或溢出，但不要求与中文参考图逐字同宽。

## 6. 响应式规则

- `1536 × 1024` 是严格像素级验收基线。
- `1440 × 900`、`1366 × 768` 保持相同比例和信息层级，允许按比例压缩间距与字号，不得出现滚动条遮挡。
- 移动端优先显示登录卡，左侧大型插画与指标区折叠或隐藏。
- 移动端适配不得改变桌面主基线的尺寸和定位。

## 7. 错误处理

- 必填校验在对应字段附近显示，不改变卡片整体宽度。
- 登录请求期间主按钮显示加载态并避免重复提交。
- 登录失败沿用统一请求层消息和 `traceId`。
- 未配置第三方登录显示信息提示，不跳转到无效地址。
- 资产加载失败必须提供品牌文字或可理解的替代内容，不能显示破图图标。

## 8. 验证与完成标准

### 8.1 视觉验证

1. 在 Chromium 中打开 `/auth/login`。
2. 固定 `1536 × 1024`、浅色、简体中文和相同表单状态。
3. 分别打开参考图和实现截图。
4. 使用透明叠加与并排比较检查坐标、比例、色彩、阴影、图标和字形层级。
5. 修复所有肉眼可见差异后重新截图，直到 `design-qa.md` 写明 `final result: passed`。

视觉 QA 不接受以下替代证据：仅构建成功、仅页面可访问、仅 HTTP 200、仅人工描述“接近”。

### 8.2 功能验证

- 前端类型检查通过。
- 前端生产构建通过。
- 登录页 Playwright E2E 通过。
- 正确账号可登录并跳转预期首页。
- 错误账号显示错误信息和 trace id。
- 记住账号、忘记密码、语言切换、主题切换和第三方入口行为通过。
- 主验收视口无水平或垂直溢出。

## 9. 不在本次范围

- 修改后端认证接口、Token 策略或权限模型。
- 修改数据库 Schema。
- 实现新的 Google OAuth 后端 Provider。
- 统一重构扫码登录、忘记密码和 OAuth 回调页面的整体视觉。
- 发布、部署或触发生产流水线。
